# React + Vite + TypeScript front end, JSON data in the repo, no backend

Date: 2026-11-02 · Status: accepted

## Context

One user, local hosting, a few dozen records, a bespoke understated UI. The deciding constraints are durability of done-marks and a design that stays coherent.

## Options

- **React + Vite + TS, JSON in repo, file-backed progress via a Vite middleware** — proven stack, typecheck in the gate, data reviewable in git / a dev-server-only persistence path.
- **Python FastAPI + static HTML** — matches Shane's Python strength / two toolchains for one small UI, weaker component tooling.
- **Static HTML + localStorage only** — zero build / state lost on cache clear, not inspectable.
- **Supabase or any hosted backend** — unnecessary for one user; adds auth and secrets.

## Decision

The first option. Progress is written to `data/progress.json` by a small Vite dev-server middleware with a `localStorage` fallback, so the static build still works. Plain CSS with custom properties instead of a utility framework, because the look is typography-led and small.

## Revisit when

- A Canvas refresh script needs to run on a schedule (then a Python entry point joins the repo under `scripts/`).
- The app is served to anyone other than Shane.

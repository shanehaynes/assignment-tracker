## Several sessions may be running right now

More than one Claude session may work in this repo at once, and none can see another's uncommitted changes. For any subagent, workflow or fan-out, follow the [parallel-agents skill](.claude/skills/parallel-agents/SKILL.md) (a pinned copy — never edit it here; see its `VENDORED` file). A `PreToolUse` hook refuses a writing subagent whose brief has no `Lane:` line.

- **Never work in the primary checkout** (the clone that owns `.git`). It stays on `main`, clean. Start every task, including one-liners, with:
  `bash .claude/skills/parallel-agents/scripts/lane.sh new <type>/<slug> "<files you will touch>"`
  It prints other sessions' claims — read them before you start.
- **Look before discarding.** No `reset --hard`, `clean -f`, `checkout -- .`, `restore`, `branch -D`, `worktree remove --force`, `push --force` without reading what would be lost. Stash only with `-m "<unique tag>"`, apply by SHA, never `pop`. (Not mechanized yet; see STATUS.md.)
- **Never copy files between branches or worktrees.** Merge instead.
- **Never kill servers by name.** Kill the PID on your own port.
- After your PR merges: `lane.sh tidy`, then `lane.sh tidy --yes`.

## Shared state

| Resource                                      | Treatment           | Mechanism                                                                                         | Notes                                                |
| --------------------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Primary checkout                              | orchestrator-owned  | `lane.sh new` for every task                                                                      | read-only for everyone else                          |
| Working tree, `node_modules`, `dist`          | partition           | one worktree per lane; `.claude/lane-setup.sh` installs deps                                      |                                                      |
| Dev port                                      | partition           | `dev/port.ts` → `lane.sh port`; strict port                                                       | primary 5173; lanes hashed into 5200–5999            |
| `data/progress.json`                          | partition           | written by each checkout's own dev server                                                         | commit it only from the primary checkout, on purpose |
| `data/assignments.json`, `data/semester.json` | hot file            | one lane edits data at a time; the validation test is the gate                                    | regenerated by extraction, not hand-merged           |
| Gate-protected paths                          | orchestrator-owned  | `data/*.test.ts`, `tests/acceptance/**`, `vite.config.ts`, `.github/`, `.claude/`, `package.json` | a lane that believes a test is wrong reports it      |
| `STATUS.md`, `CLAUDE.md`, `package-lock.json` | hot file            | edit only your own row / only with a reason                                                       |                                                      |
| Decision records                              | partition           | `docs/decisions/YYYY-MM-DD-<slug>.md`                                                             | date + slug, never a counter                         |
| Merge, PR creation                            | orchestrator-owned  | squash-merge via PR                                                                               |                                                      |
| Canvas                                        | external, read-only | pulled through Shane's signed-in Chrome session, never a stored token                             | no writes to Canvas, ever                            |

## Environments and secrets

None. There is no `.env`; the app reads committed JSON. Progress is written by the dev server to `data/progress.json`. Deploy: none — see [docs/decisions/2026-11-02-deploy-target.md](docs/decisions/2026-11-02-deploy-target.md).

## Merging

Squash-merge; `main` requires branches up to date, so after each merge the next PR needs `git merge origin/main && git push` and a green CI run. Every PR is based on `main` — never stack. Before opening several PRs at once, prove they combine (parallel-agents' combine check, with the gate).

Held for Shane (never merged by an agent): `.github/`, `.claude/settings.json`, `.claude/skills/`, `package.json` dependencies.
